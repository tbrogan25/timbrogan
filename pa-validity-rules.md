## Validity Rules

You will work with the following validity outcomes:

* **Valid**
* **Failed Match:** The signature is properly formatted but the signer is not registered to vote with the information they provided.
* **Unusable:** The signature is missing one or more of the six core pieces of information, regardless of whether the signer is registered to vote or not.

As long as there is an attempt by the signer to write all six core pieces of information and you find a match, a signature can be considered valid.

The six core pieces of information are:

* Signature
* First AND last name
* Street number
* Street name
* City, Boro, or Township
* Date

#### What's Allowed:

* Reasonable nicknames
* Initials for first and/or last name, if only one voter matches the initials at the address
* Spelling errors, or switched/missing letters
* Messiness, but the legible letters or clues clearly point to only one voter at an address
* Information is in the wrong boxes, as long as all of the information is present in the row
* Missing or incorrect street suffixes
* Shortened street names
* Ditto marks to indicate that their address is the same as the above signer's address

#### What's Not Allowed:

If any of the six core pieces of information are clearly missing and _not included anywhere else on the row_, it is **Unusable**.&#x20;

If the information is included somewhere else on the row, it can be valid. Example below:

<figure><img src=".gitbook/assets/image (226).png" alt=""><figcaption><p>The street name is included in the "House No." box - this can be valid</p></figcaption></figure>

If there are any clear clues in the signatures that differ from a potential match, do not match it. This would be an example of a **Failed Match**.

Basically, none of the handwritten name or address should clearly conflict with the voter you're matching it to. For example, if the written last name clearly includes a "gg" but the voter's last name doesn't, that's a sign it's not a valid match.

Also, street numbers must match, within reason. They can be messy and you can still validate it if a number looks a little different. But clearly different numbers cannot be matched.

Messiness is allowed. Shortening is allowed. Initials are allowed. Misspelling is allowed.

But if any of the six core pieces of information do not visibly align with a voter, the signature is invalid.

### Failed Match

Choose **Failed Match** when the signature is formatted correctly but the information does not confidently match a voter

### Unusable

Choose **Unusable** when one or more of the six pieces of core information is clearly missing

### County Rules

Each petition sheet includes a county box, where the county is written by the signature-gatherer.&#x20;

<figure><img src=".gitbook/assets/image.png" alt=""><figcaption></figcaption></figure>

You must tag the county of the sheet in the COUNTY dropdown in the top left.

This only needs to be done once per sheet and you will be prompted to do so if it isn't filled out.

There are two sides to this sheet. If you encounter a backside, there is no county box. Instead, the county should be handwritten somewhere on the sheet, usually the top right. Example below:

<figure><img src=".gitbook/assets/image (227).png" alt=""><figcaption></figcaption></figure>

If there's no county, select NO COUNTY.

If you find a match from a different county than the one written on the sheet, ignore it. Validate it as you normally would.

{% hint style="warning" %}
You don't need to think about counties when validating; only when you're tagging the sheet
{% endhint %}

### Dates

Dates are a new concept to us. They are very important to the state of PA, though.

Not only are they one of the six core pieces of information that are required to be on the sheet, but:

The **year** must also be present.

If the year is not present in the date, don't mark the sig **Unusable**.

We need to still validate it to retain the voter's information, but also indicate that the year is missing.

Instead, simply check this checkbox, and _then_ validate it.&#x20;
